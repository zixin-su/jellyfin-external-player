# 需求总结

本文档总结初始实现阶段确认下来的产品需求。

## 目标

构建一个 Windows 友好的 Jellyfin 客户端。界面仍然使用 Jellyfin Web，但当用户点击播放按钮时，改为调用本机外部播放器播放。

## 用户需求

1. 客户端本质上是 Jellyfin Web 的浏览器套壳。
2. 用户仍然通过原始 Jellyfin Web 页面登录。
3. 应用需要提供设置页面，用于配置：
   - Jellyfin 服务地址。
   - 外部播放器 exe 路径。
   - 外部播放器参数模板。
   - 是否拦截播放。
   - 是否优先使用 Jellyfin 流地址。
   - STRM/本地路径相关行为。
   - 鼠标滚轮方向修正。
4. 配置外部播放器后，点击 Jellyfin 播放按钮应调用外部播放器。
5. STRM 媒体不能只依赖本机读取 `.strm` 文件，因为客户端 PC 可能访问不到 NAS 内部路径。
6. 优先播放目标应为 Jellyfin HTTP 流地址，使外部播放器通过 Jellyfin 服务拉流。
7. 如果用户确实希望直接访问文件路径，仍然保留可选路径映射能力。
8. 海报中间播放按钮和详情页播放按钮需要被拦截。
9. 非播放功能必须保持 Jellyfin 原逻辑：
   - 收藏。
   - 已观看状态。
   - 更多菜单。
   - 详情页播放以外的其他工具按钮。
10. 剧集和季的封面播放应尽量符合 Jellyfin 逻辑：
    - 剧集：优先播放 Next Up，找不到则播放第一集。
    - 季：优先播放未看完的集数，再播放未观看集数，再播放第一集。
11. 打包版本升级时，应能迁移登录态和设置。
12. 缩放快捷键需要稳定可用：
    - `Ctrl+-` 缩小。
    - `Ctrl+=` / `Ctrl++` 放大。
    - `Ctrl+0` 重置缩放。
13. 鼠标滚轮方向需要符合用户习惯，并提供开关用于关闭修正。
14. 运行数据、缓存、发布临时目录不得提交到源码仓库。

## 非目标

- 不重写 Jellyfin Web UI。
- 不替换 Jellyfin 登录认证。
- 不实现自研播放器。
- 不要求客户端直接访问 NAS 路径。
- 不把用户登录态、Cookies、缓存、设置或本地媒体路径上传到公开仓库。

## 当前行为

- 应用通过 preload 脚本注入 Jellyfin Web 页面。
- preload 脚本识别真正的播放控件，并把播放请求发送给 Electron 主进程。
- 主进程通过 Jellyfin API 解析媒体信息、播放信息、剧集 Next Up 和季内单集。
- 主进程调用用户配置的外部播放器，并传入解析后的 URL 或路径。
- 默认优先使用 Jellyfin HTTP 流地址，而不是直接文件路径。
